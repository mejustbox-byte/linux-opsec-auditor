# ADR-001: Python 3.12, offline evidence first, bounded local reads

Status: Accepted for experimental MVP on 2026-10-09; supersedes the proposed
onboarding ADR. Python 3.12+ on Linux, standard library runtime and unittest suite.
A hash-locked setuptools/build toolchain produces wheel and sdist. No pytest,
Ruff or mypy requirement is introduced in the first release: dependency footprint
is minimized and substantive tests use unittest. Static type checking and lint
can be added in a separately pinned toolchain; compilation is not a substitute.

Why: JSON, argparse, fd-relative filesystem operations and deterministic unit tests
are available without runtime dependencies. Normalized facts allow useful policy
feedback before risky platform collectors exist. A minimal local collector detects
explicit risky SSH fragments and unsafe mode/owner facts without invoking tools.

Alternatives: Go offers a single binary and easier target deployment; Rust offers
strong memory guarantees but a steeper parser/packaging ramp; shell was rejected
as the primary language due to safe parsing/schema/report requirements.

Consequences: Python 3.12 must already be provisioned in any laboratory that runs
local collection; distribution defaults may be older. Do not install Python on an
audit target as part of an audit. Offline evaluation can run on a separate trusted
Linux workstation. No promise of remote agentless collection or host attestation.

Open decisions: SSH transport and strict known_hosts strategy; authenticated offline
vendor advisory format; baseline normalization/signing; schema migration; per-object
findings; privileged read allowlist if ever needed. Each must preserve read-only
behavior, confidentiality and the unknown-on-insufficient-evidence contract.
