# ADR-001: Python 3.12, нормализованное evidence и ограниченное чтение

Статус: принято для экспериментального MVP 2026-10-09; заменяет предложенный ADR
onboarding. Python 3.12+ на Linux, stdlib runtime и unittest. Сборка wheel/sdist через
зафиксированные по хешам setuptools/build. pytest/Ruff/mypy пока не нужны: содержательные
тесты используют unittest, а проверка компиляции не заменяет статический анализ.
Добавление lint/type-check требует отдельной воспроизводимой фиксации инструментов.

Причины: JSON, argparse, fd-операции и детерминированные тесты доступны без runtime
зависимостей. Нормализованные факты позволяют проверить политику до реализации
рискованных platform collectors. Локальное чтение выявляет явные SSH-флаги и опасные
mode/owner без исполнения команд.

Альтернативы: Go — единый binary и удобная доставка; Rust — сильные гарантии памяти,
но более высокая цена первой итерации; shell отвергнут как основной язык из-за
требований безопасного parsing/schema/report.

Следствия: Python 3.12 должен быть заранее подготовлен в лаборатории; системный Python
дистрибутива может быть старше. Не устанавливать его на целевой хост в процессе аудита.
Offline-оценка возможна на отдельной доверенной Linux-машине. Удалённый agentless
сбор и аттестация хоста не обещаются.

Открытые решения: SSH/known_hosts; формат и подлинность offline advisories; baseline
normalization/signing; schema migration; findings по отдельным объектам; возможный
allowlist привилегированных чтений. Всё должно сохранять read-only, конфиденциальность
и unknown при недостатке evidence.
