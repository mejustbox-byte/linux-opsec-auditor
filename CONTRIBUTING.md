# Участие в проекте

Документация и пользовательские описания — на русском. Команды, пути, ID, JSON-ключи
и кодовые идентификаторы не переводить. Сначала прочитайте требования, модель угроз
и матрицу проверок. Не меняйте настройки аудируемого хоста и не добавляйте исправления.

Используйте только синтетические фикстуры без реальных секретов/инвентарей. Для нового
правила нужны source/права, OS/version applicability, rationale, severity, evidence,
remediation, ограничения и случаи pass/fail/unknown/not_run/повреждённый вход.
Контейнер не подтверждает работу ядра/LSM на хосте. Незнакомые платформы не наследуют pass.

Перед PR выполните `bash tools/setup_environment.sh`. Не допускайте нулевого набора
тестов, отключения assertions или обхода TLS/hash verification. Проверьте git diff,
отсутствие секретов и неизменность lockfile при установке. Опишите проблему, итоговое
поведение, реальные выполненные проверки и оставшиеся ограничения на русском.
Секреты и сырые private reports не публикуйте в PR/CI artifacts.

Изменение стека, SSH transport, привилегированных чтений, advisory trust и baseline
signing требует ADR. Release создаётся из точного прошедшего ревью commit через
ограниченный workflow. Существующие tags не передвигать; для изменений нужна новая версия.
