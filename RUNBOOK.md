# Эксплуатация и диагностика

Продукт — разовая команда, не служба. Нет порта, HTTP healthcheck, daemon, БД или
процесса, который должен переживать snapshot. Не запускать collect автоматически
на production. Сначала согласуйте хост, объём данных, пользователя и приватный вывод.

## Обычный цикл

1. Проверьте версию и checksum инструмента, заранее подготовленный Python и цель аудита.
2. Создайте приватный каталог вне checkout (`mktemp -d`), затем collect в новый snapshot.
3. Выполните audit с нужным format и --fail-on incomplete; сохраните exit status,
не скрывайте его через pipe. Unknown ожидаем для большинства локальных источников.
4. Ревью findings: severity — важность политики, confidence/source — доверие к evidence.
   Fail не разрешает автоматическое исправление. Для drift fail — изменение, не уязвимость.
5. Храните отчёт приватно по согласованной retention-политике. Не коммитьте snapshot,
raw outputs или реальную инфраструктуру; public examples только synthetic.

## Ошибки

| Симптом | Проверка и безопасное действие |
|---|---|
| Exit 2 | Неверный JSON/тип/дата/повтор, отсутствие файла, symlink или недоступное чтение; не выводить payload в публичный issue |
| Файл вывода уже есть | Выбрать новое имя; инструмент намеренно не перезаписывает |
| Небезопасный каталог | Использовать собственный приватный каталог 0700, не менять security policy чужого каталога |
| Unknown всей платформы | Версия/архитектура вне candidate matrix; не подменять platform ради pass |
| Unknown свежести | Сверить UTC/время источника; обновлять только реальное наблюдение, не дату старых данных |
| SSH unknown | Include/Match/effective не разрешены; нужна независимая разрешённая проверка |
| LSM unknown | Host context не установлен; контейнер и индикатор SELinux не дают host evidence |
| Exit 1 | Ревью конкретного evidence и ограничения; remediation — рекомендация оператору |
| Exit 3 | Неполнота без fail при строгом пороге; собрать недостающие разрешённые факты |
| I/O завис | ФС/ядро могут блокировать чтение; прервать команду, исследовать отдельно, не обещать hard timeout |

Чтение может создавать atime/audit записи. Сравнивайте охраняемую конфигурацию,
а не все побитовые состояния ФС. Данные compromised root/ядра нельзя аттестовать этим CLI.

## Обновления и инциденты

Новая версия — новый venv и проверенные assets, затем synthetic smoke. Исторические
reports и tags сохраняются; сверяйте policy/rule versions. Для sensitive bug используйте
SECURITY.md, не публичный dump. Логи CI/API могут содержать signed download URLs:
не переносите такие access-ссылки или credentials в публичные документы.
Если native upload cloud worker не авторизован, используйте штатный Actions workflow,
не обход аутентификации и не новый token. Правила публикации — RELEASE-CHECKLIST.md.
Полная команда установки/удаления — INSTALL.md, CLI — CORE-CONTRACT.md.
